## Что нужно исправить до Sprint 1

### 1. Current-line pricing

Сейчас latest snapshots выбираются отдельно для каждой line. После движения
O2.5 → O2.75 система может продолжить показывать и оценивать старую O2.5 как
доступный рынок.

**Требование:** для prediction должна использоваться только последняя актуальная
line для `bookmaker + market + selection`.

### 2. Snapshot ingest

Последний snapshot ищется с фильтром по line. Из-за этого последовательность
2.5 → 2.75 → 2.5 с прежней ценой потеряет последний возврат линии.

**Требование:** сравнивать новый snapshot с последним состоянием selection
**независимо от line**.

### 3. Stale/missing-data protection

Сейчас `odds_age_seconds` только выводится, но stale odds всё равно могут дать
BET. Аналогично, при отсутствии противоположной цены `market_probability=null`,
но решение всё равно может стать BET.

**Требование:**
- missing opposite side → `PASS` / `DATA_UNAVAILABLE`
- stale odds → `PASS` или `WATCH` по явному threshold
- snapshot после kickoff не использовать
- future/negative age считать provider error

### 4. Market disagreement boundary

При disagreement ровно `0.07` код возвращает BET, одновременно добавляя
`REQUIRE_DEEP_REVIEW`.

**Требование:** условие должно быть `>= 0.07`.

### 5. `model_runs.inputs_json` reproducibility

Текущий тест не восстанавливает prediction только из `inputs_json`: он читает
selection, line и bookmaker_odds из `MarketPrediction` и не перепроверяет
`market_probability`, `edge`, `decision` и reason codes.

**Требование — сохранять/фиксировать:**
- `model_version`
- snapshot IDs и prediction cutoff
- конфигурацию и decision thresholds
- feature flags / market mapping
- полный набор входов или их version/hash

Добавить тест, который восстанавливает **всю** prediction и сравнивает **все** поля.

### 6. `/predictions/value`

Переменная `latest_run` вычисляется, но не используется. Endpoint сейчас
возвращает старые predictions и дубликаты всех предыдущих запусков.

**Требование:** последний релевантный model run для каждого fixture/market
и явная фильтрация допустимых decisions.

### 7. Synthetic/live provenance

При повторном ingest существующий fixture не обновляет `data_source`, а API
формирует synthetic warning глобально по всей БД. В смешанной live/replay базе
provenance может стать неверной.

**Требование:** источник нужен на уровне fixture / snapshot / model run
и должен определяться для конкретного ответа.

### 8. `/health`

После ошибки подключения к БД endpoint продолжает выполнять DB-запросы, поэтому
вместо `degraded` может вернуть 500.

**Требование:** все зависимые запросы — внутри защищённого блока.

### 9. Gate 0 harness

- The Odds API сейчас запрашивает `totals,spreads`, но проверяет `team_totals`
  и BTTS, которых в ответе заведомо не будет
- xG нельзя считать подтверждённым просто по непустому `fixtures/statistics`
- Historical odds нельзя выставлять `PARTIAL` без живой проверки
- SportMonks probe не реализован
- stats coverage не входит в формальный gate
- coverage нужно проверять на 20–30 матчах, а не на одном fixture
- исправить запуск на Windows без обязательного `PYTHONUTF8=1`

### 10. DB / infra

До Sprint 1 подготовить:
- provider namespace / composite keys для fixtures, leagues и teams
- полный `.env.example`
- Docker Compose smoke test
- CI с PostgreSQL integration tests
- pinned / locked dependencies

Не нужно сейчас реализовывать frontend, Telegram или последующие спринты, но
**документация не должна утверждать полное соответствие §47**, пока Compose
содержит только backend и postgres.
