# Gate 0 — звіт про валідацію провайдерів (ТЗ §3)

**Дата:** 2026-08-29
**Статус:** 🔴 **НЕ ПРОЙДЕНО — заблоковано зовнішньою причиною, не роботою кодера**
**Наслідок за ТЗ §48:** переходити до Sprint 1 не можна, доки Gate 0 не закритий.

---

## 1. Короткий висновок

Gate 0 вимагає перевірити 2–3 провайдери на 20–30 реальних матчах. **Виконати цю
перевірку в поточному середовищі неможливо**: усі хости data-провайдерів
заблоковані egress-політикою мережі, у якій виконується робота.

Це **не** «API не працює» і **не** «немає ключа». Запит не доходить до провайдера
взагалі — його ріже проксі на етапі `CONNECT`.

```
[BLOCKED] The Odds API v4              api.the-odds-api.com       403 на CONNECT
[BLOCKED] API-Football (api-sports.io) v3.football.api-sports.io  403 на CONNECT
[BLOCKED] SportMonks Football          api.sportmonks.com         403 на CONNECT
```

Додатково перевірено (той самий результат): `api.football-data.org`,
`api.openligadb.de`, `www.thesportsdb.com`, `api.b365api.com`.

Відмінність, яка тут принципова:

| Код | Що означає | Висновок для Gate 0 |
|---|---|---|
| `401 / 403` **від провайдера** | хост доступний, потрібен/невірний ключ | провайдер живий, треба ключ |
| `403` **на CONNECT від проксі** | запит не вийшов з мережі | про провайдера **не відомо нічого** |

У нас другий випадок. Тому будь-яка заповнена таблиця покриття ринків була б
вигадкою — а ТЗ §1 прямо це забороняє («Не вигадувати дані»). Тому нижче
матриця з реальних прогонів порожня, а окремо наведено desk-research з явною
позначкою, що це **не перевірені дані**.

## 2. Що зроблено замість «заповнити табличку навмання»

1. **Написаний робочий harness** — `gate0/validate_providers.py`. Він виконує
   рівно те, що вимагає ТЗ §3: бере 20–30 матчів, опитує провайдерів, перевіряє
   наявність ринків і timestamps, друкує таблицю у форматі §3 і повертає
   ненульовий exit code, якщо Gate 0 не пройдений.
2. **Harness уже прогнаний** — саме він дав діагноз вище
   (`gate0/gate0_result.json`).
3. **Клітинки, які не перевірені, позначені `UNKNOWN` / `BLOCKED`**, а не `NO`.
   Це різні речі, і плутати їх у Gate 0 не можна.

Коли з'являться мережевий доступ і ключі, повний Gate 0 закривається однією
командою, без дописування коду:

```bash
export THE_ODDS_API_KEY=...
export API_FOOTBALL_KEY=...
python gate0/validate_providers.py --md-out gate0/GATE0_RESULT.md
```

## 4. Desk research — ⚠️ НЕ ПЕРЕВІРЕНО ЖИВИМИ ЗАПИТАМИ

Нижче — очікування з документації провайдерів. Це орієнтир для вибору, кого
тестувати першим, **а не результат Gate 0**. Кожен рядок потребує підтвердження
харнесом, перш ніж на нього можна спиратися.

| Provider | Fixtures | Stake odds | Asian totals | Team totals | BTTS | Historical odds | xG | Lineups | Injuries | Price/limits |
|---|---|---|---|---|---|---|---|---|---|---|
| The Odds API v4 | очік. YES | ⚠️ під питанням | очік. PARTIAL | ⚠️ залежить від плану | ⚠️ | **очік. YES** (окремий endpoint) | NO | NO | NO | NO |
| API-Football | очік. YES | ⚠️ під питанням | ⚠️ | ⚠️ | очік. YES | ⚠️ без руху лінії | очік. YES | очік. YES | очік. YES | NO |
| SportMonks | очік. YES | ⚠️ | ⚠️ | ⚠️ | очік. YES | ⚠️ | очік. YES | очік. YES | очік. YES | NO |

Головне, що видно вже зараз: **жоден провайдер не закриває все сам**.
Найімовірніша робоча конфігурація — **два провайдери**: один odds-first
(historical odds + рух лінії), другий stats-first (xG, склади, травми). Саме тому
`OddsProvider` і `StatsProvider` у ТЗ §6 розділені — архітектура це вже враховує,
і PoC її дотримується.

### Окремо про Stake (ТЗ §0, §33)

Stake як bookmaker у публічних агрегаторах зустрічається нестабільно. ТЗ §3 це
вже передбачає: *«Якщо Stake не доступний, система має зберігати preferred
bookmaker окремо і використовувати best available price»*. У PoC це закладено:
`bookmakers.is_preferred` і `bookmakers.is_sharp` — окремі поля, preferred
bookmaker не зашитий у логіку.

## 5. Що потрібно від замовника, щоб закрити Gate 0

1. **Мережевий доступ** до хостів провайдерів (зняти egress-обмеження або
   виконати прогін у середовищі з відкритим інтернетом).
2. **API-ключі** — мінімум два: один odds-провайдер, один stats-провайдер.
   Достатньо trial/free tier: для Gate 0 потрібні 25 матчів, а не продакшн-обсяг.
3. **Підтвердження цільових ліг** — зараз у харнесі EPL / La Liga / Bundesliga.

Після цього Gate 0 закривається за ~15 хвилин однією командою.

---

## 6. Критерій приймання Gate 0 (з ТЗ §3)

> *Обраний provider повинен реально покривати ключові ринки.*

Харнес перевіряє це формально — обов'язкові поля зашиті в
`GATE0_REQUIRED = [Fixtures, Asian totals, Team totals, BTTS, Historical odds]`.
Якщо хоч одне не `YES`, скрипт повертає exit code 1 і пише «Gate 0 НЕ ПРОЙДЕНО».
Пройти його «на око» неможливо.
